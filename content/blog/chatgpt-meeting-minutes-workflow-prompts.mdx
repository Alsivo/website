本記事では、会議の音声やメモから「短時間で」「抜け漏れを減らし」「社内で安全に」議事録を作る手順を、初心者でも再現できる形でまとめます。対象範囲は「文字起こし（音声→テキスト）から配布・保管」までです。会議内容の意思決定には触れず、作業プロセスに絞ります。

## 本記事で得られることと対象範囲の確認
- 得られること
  - 5ステップの標準ワークフロー
  - 文字起こし手段の選び方（Zoom/Teams/外部/Whisper）
  - ChatGPTに渡すための前処理とプロンプト設計
  - すぐ使える議事録テンプレ・チェックリスト・配布方法
  - 半自動化（Zapier/Make）の概要とセキュリティの注意点
- 対象範囲
  - 音声録音は済んでいる前提（簡単な録音環境の注意は記載）
  - 個社の機密ポリシーや法令順守は必ず社内基準を優先

## 全体像：5ステップで回す議事録ワークフロー
1) 文字起こしを取得（自動機能 or 外部ツール）
2) 前処理（話者整理・雑談除去・機密の匿名化）
3) ChatGPTで生成（プロンプト＋テンプレ適用）
4) 品質向上（チェックリスト＋再プロンプト）
5) 配布・保管（Docs/Notion・版管理）

所要時間の目安（30〜60分程度）
- 15分：文字起こし取得
- 10分：前処理
- 10〜20分：生成と修正
- 5分：配布・保管

実際の時間は音質・専門性・会議の長さで変動します。

## 会議前の準備：テンプレ決定・録音環境・役割分担
- テンプレを固定化
  - 章立て（出席者／議題／決定事項／課題／次回までのアクション／期限）を事前合意
  - 固定テンプレを全会議で流用し、差分だけ更新
- 録音環境の基本
  - マイクは会場中央に1台より、発言者近くのマイク（ヘッドセットや指向性マイク）が有利
  - ハウリング・空調音対策：静かな部屋、PCのファン音を避ける
- 役割分担
  - 主催：録音開始・議題管理
  - 書記：タイムスタンプの軽メモ（後で要点確認に有効）
  - 監督：決定事項の最終確認（会議終盤に口頭で再確認）

## 文字起こしの取り方：ZoomやTeams、外部ツール、Whisper
- 会議ツールの自動機能（Zoom/Teams など）
  - 利点：ワンクリックで取得、話者名が付く場合あり（参加者のサインイン状況等に依存）
  - 注意：プランや設定により精度・機能が変わる。社内での使用可否・保存先を確認
- 外部の文字起こしサービス
  - 利点：UIがわかりやすく、要約やスピーカー分離に強いものも
  - 注意：機密情報の取り扱い・データ保存期間・海外保管の有無を事前確認
- Whisper（OpenAIの音声認識モデル）
  - 利点：高精度で多言語対応。ローカル実行が可能なためデータを外部に出しにくい運用ができる
  - 注意：PC性能やセットアップが必要。話者分離は別ツール併用が必要な場合あり

選び方の目安
- スピード重視：会議ツールの自動トランスクリプト
- セキュリティ重視：社内承認済みの外部サービス or Whisperローカル
- 精度重視：高品質マイク＋ノイズ少なめ＋専門語辞書（固有名詞リスト）の併用

## 文字起こしを整えるコツ：話者分離、ノイズ対策、表記統一
- 話者分離（スピーカーラベリング）
  - 事前に参加者名簿を用意し、文字起こしの「Speaker 1→佐藤」などに貼り替える
- ノイズ対策
  - 録音後に気になるノイズは、オーディオ編集（例：Audacity等の基本的なノイズ低減機能）で軽減可能
- 表記統一
  - 会社名・製品名・略語・部門名を用語リスト化（例：SFA=営業支援システム）
  - 数字表記（半角/全角、金額の単位）を統一

## ChatGPTに渡す前の前処理：雑談除去、機密情報の匿名化
- 雑談・関係ない小話を削除（文字数を減らし、誤要約を防止）
- 機密情報の匿名化（例）
  - 顧客名：株式会社〇〇 → [顧客A]
  - 具体金額：1,238,000円 → [金額X]
  - 個人情報：氏名・メール → [個人名1]／[メールA]
- 匿名化メモを添付（例：「[顧客A]=株式会社〇〇」）→最終配布版には含めない

## 基本プロンプト設計：役割・出力形式・粒度・評価基準
- 役割指定：あなたは「日本語ビジネス文書の議事録作成アシスタント」
- 出力形式：固定テンプレに準拠
- 粒度：要点中心／冗長な言い換え禁止／引用は必要箇所のみ
- 評価基準：事実ベース、曖昧箇所は「要確認」を明示

入力例（コピペでOK）
```
あなたは日本語ビジネス文書の議事録作成アシスタントです。以下の条件で、与えた発言録から議事録を作成してください。
- 出力章立て：出席者／議題／決定事項／課題／次回までのアクション／期限／エグゼクティブサマリ（5行）
- 粒度：会議の決定と理由が伝わる最小限。冗長な比喩は不要
- 事実性：不明点・推測は書かず、「要確認」を付記
- 書式：箇条書き中心。箇条書きは1行1論点
- 用語：用語リストに合わせる（後述）

【会議メタ情報】
- 会議名：{会議名}
- 日時：{YYYY-MM-DD} {HH:MM}-{HH:MM}
- 目的：{目的}
- 用語リスト：{SFA=営業支援システム, ○○製品=正式名称…}

【発言録】
(ここに整えた文字起こしを貼り付け)
```

## 長文対策：分割投入、段階要約、確認質問で精度を上げる
- 分割投入
  - 目安：1セクション3,000〜5,000文字で分割（議題ごとが理想）
  - 各チャンクの冒頭に「議題名」「時刻範囲」を明記
- 段階要約
  - ステップ1：チャンクごとに要点・決定・未決事項を抽出
  - ステップ2：全チャンクの要約を統合し、最終議事録に再構成
- 確認質問
  - ChatGPTに「不明点リストを出して」→不足情報を人間が補足→再生成

分割時の指示例
```
これから会議発言録を3分割で送ります。各パートで「要点・決定事項・ToDo」を抽出し、最後に統合します。準備ができたら「準備OK」とだけ答えてください。
```

統合時の指示例
```
これまでの3本の要約を統合し、重複を除去して最終議事録を作成してください。章立ては指定どおり、曖昧な箇所には「要確認」を付けてください。
```

## すぐ使えるプロンプト集
1) 議事録生成（標準）
```
以下の発言録から、指定の章立てで議事録を作成。決定事項と根拠は必ず対で記載。未決は「保留」と明記：
【発言録】
...
```

2) 決定事項とToDo抽出
```
発言録から「決定事項」「ToDo（担当・期限）」のみを抽出。未決は「保留」。担当者不明は「担当TBD」：
【発言録】
...
```

3) 担当者と期限の整理
```
以下のToDoを「担当者／タスク／期限（YYYY-MM-DD）／依存関係」で再整形。期限が日付でない場合は推奨期限案を1つ提案：
【ToDo一覧】
...
```

4) 重要発言の引用
```
方針転換・承認・リスク指摘に該当する発言のみ、原文引用で抜き出し。各引用に時刻と話者を付与：
【発言録】
...
```

5) 5行サマリ（エグゼクティブサマリ）
```
以下の議事録を5行で要約。1行1論点で、決定・理由・次アクションが伝わる形に：
【議事録】
...
```

## 出力テンプレート：日本語ビジネス標準の章立て
- 出席者：氏名（所属）／欠席者
- 議題：議題1／議題2／...
- 決定事項：番号付きで簡潔に（例：D1, D2）
- 課題：番号付き（例：I1=未解決）
- 次回までのアクション：担当／タスク／期限
- 期限：上記アクションの集約一覧
- エグゼクティブサマリ（5行）：意思決定の要点のみ

そのまま貼れる雛形
```
【出席者】
- 
【議題】
- 
【決定事項】
- D1：
- D2：
【課題】
- I1：
【次回までのアクション】
- 担当：／タスク：／期限：
【期限】
- タスク：／期限：
【エグゼクティブサマリ（5行）】
1)
2)
3)
4)
5)
```

## 品質向上の反復：チェック項目と赤入れ用プロンプト
- ファクトチェック項目
  - 人名（漢字・英字表記）
  - 日付・時刻・場所
  - 金額・数量・単位
  - 固有名詞（製品・顧客・プロジェクト名）
- 一貫性チェック
  - 決定事項とアクションに齟齬がないか
  - 略語の初出に説明があるか
- 赤入れ用プロンプト
```
以下の議事録の曖昧・矛盾・抜けを洗い出し、「該当箇所」「理由」「改善案」で出力。推測は避け、必要なら「要確認」を提案：
【議事録】
...
```

## 配布と保管：GoogleドキュメントやNotion、版管理
- 配布
  - Googleドキュメント：共有リンクは「閲覧のみ」＋コメント権限を必要者に限定
  - Notion：テンプレ化して、各会議ページを複製運用
- ファイル名規則（例）
  - YYYYMMDD_会議名_v1（作成者イニシャル）
  - 版管理はv1→v2→final、最終版以外はアーカイブへ
- メタ情報の残し方
  - ページ冒頭に「目的／参加者／機密区分」

## 半自動化のヒント：Zoom/Teams→文字起こし→ChatGPT→保存
- Zapier/Makeの概要
  - トリガ：録画ファイルの保存（クラウドストレージなど）
  - アクション1：文字起こしサービスに送信→テキスト取得
  - アクション2：ChatGPT（API）で要約・議事録生成
  - アクション3：Googleドキュメント/Notionへ自動保存
- 注意点
  - APIキー・接続先の権限管理、ログの保管場所を確認
  - 初回は小規模会議でテストし、誤動作時は自動配布を止める設計に

## セキュリティとコンプライアンス
- 原則
  - 社内ポリシーと契約（NDA等）を最優先
  - 個人情報・機密は可能な限り匿名化
- ツール選定の観点
  - データの保存場所・保存期間・第三者提供の有無
  - アカウント単位のアクセス制御・監査ログ
- ChatGPTの利用形態
  - 企業向けプラン（例：Enterprise/Teams等）では、提供元の説明として「入力データを学習に使用しない」設計が案内されている場合があります。実際の扱いは契約・最新仕様を必ず確認してください。
  - 一般向けの利用では、履歴設定や共有設定に留意し、機密は原則投入しない運用が安全です。

## トラブルシューティング
- 音質が悪い
  - マイク位置を改善、部屋を変える、ノイズ低減を実施
  - 重要箇所のみ聞き直してタイムスタンプを補記
- 専門用語が多い
  - 用語リストを作成し、プロンプトに添付
  - 固有名詞の候補スペルを複数記載
- 英語混在
  - 文字起こし時に多言語対応設定を有効化
  - ChatGPTに「和英混在で正確に引用、要約は日本語」と指示
- テキストが長すぎる
  - 議題ごとに分割し段階要約→統合
  - 「不明点リスト」を出させて不足だけ追送

## よくある質問（FAQ）
- Q：議事録の精度はどこまで上げられますか？
  - A：音質・前処理・用語リストの有無で大きく変わります。事実確認（人名・日付・金額）は人手で最終確認するのが安全です。
- Q：雑談を残すべき？
  - A：結論に関係する背景説明のみ。世間話は削除すると短時間化・精度向上に寄与します。
- Q：外部サービスは安全ですか？
  - A：サービスごとに異なります。データの保存・学習利用・保管場所を必ず確認し、社内承認を得てください。
- Q：録音が禁止の会議は？
  - A：メモベースで実施し、ChatGPTにはメモのみ投入。録音の是非は会議前に合意を取る必要があります。
- Q：途中参加・途中退出が多い会議は？
  - A：出席者は開始・終了時点で明記し、アクションは現時点の担当者で確定。後から差し替え可能にします。
