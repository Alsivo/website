日常のPython開発を短縮したい方向けに、Claude Codeを使った「渡し方・依頼の粒度・品質担保」のコツと、明日から使えるプロンプトと手順をまとめました。

## はじめに：この記事で得られることと想定読者
- 対象: Python初学者〜中級の個人開発者・現場エンジニア。
- 悩み: LLMを実案件に落とし込むとき、何をどう渡し、どの粒度で頼み、どこまで任せるかが不明。品質（テスト・型・スタイル）や既存リポジトリへの適用が不安。
- 得られること: Claude Codeを使った「設計→実装→テスト→デバッグ→リファクタ→レビュー」の再現可能なワークフロー、プロンプトの型、品質ガードレール。キーワード: Claude Code Python 開発 効率化。

## Claude Codeとは何か：できること・できないこと（安全に使うための前提）
「Claude Code」は、AnthropicのClaudeが提供するコード支援に向いた使い方・機能群の総称として本記事で用います。以下は一般的な利用イメージです。

できること（例）
- 既存コードや仕様の要約、設計のたたき台の作成
- 関数/モジュールの雛形生成、ドキュメント/型ヒント/テストの同時生成
- トレースバックやエラーログを基にした原因仮説と修正案の提示
- リファクタリング計画の提案、差分（unified diff/patch）の生成

できない/注意が必要なこと（例）
- 生成物は実行されず、必ずしも正確ではない（依存バージョンや境界条件のズレに弱い）
- 大規模リポジトリはそのまま全体を共有できない場合がある（コンテキスト上限）
- セキュリティやライセンス、機密データの扱いは人が最終判断する必要がある

前提と安全策
- すべての提案はローカルでビルド・テスト・型チェックを通す
- 小さく依頼し、小さく適用・検証する
- 依存・制約（Pythonバージョン、フレームワーク、スタイル）を最初に明示する

## 準備編：環境セットアップとClaude Codeの利用開始
最小構成で始めたい人向けのセット。

1) Pythonと仮想環境
```bash
# Python 3.11 を例に
python -m venv .venv
source .venv/bin/activate  # Windows: .venv\Scripts\activate
python -m pip install --upgrade pip
```

2) 開発・品質ツールの導入
```bash
pip install pytest pytest-cov black ruff mypy typer[all]
```

3) プロジェクト構成（例）
```
project/
  pyproject.toml
  src/
    pkgname/
      __init__.py
      main.py
  tests/
    test_main.py
```

4) pyproject.toml（品質ガードの既定）
```toml
[project]
name = "pkgname"
version = "0.1.0"
requires-python = ">=3.11"

[tool.black]
line-length = 100

[tool.ruff]
line-length = 100
select = ["E","F","I","UP","B","ANN"]
ignore = ["ANN101","ANN102"]

[tool.mypy]
python_version = "3.11"
strict = true
warn_unused_ignores = true
mypy_path = "src"

[tool.pytest.ini_options]
addopts = "-q --cov=src --cov-report=term-missing --maxfail=1"
pythonpath = ["src"]
```

5) Claude Codeの利用開始（ファイル共有の基本）
- 共有するのは「最小で十分な文脈」。まずは以下を渡すと効果的。
  - ディレクトリツリー（例: `tree -I .venv` の出力）
  - `pyproject.toml` または `requirements.txt`
  - 依頼対象のファイルと関連する小さな抜粋
  - 実行コマンド、エラーログ（トレースバック）
- 機密情報（APIキー、個人情報）は除外・マスキングしてから共有。

## 効率化の基本原則：良いコンテキストの渡し方と依頼の粒度
LLMは「明確な制約と小さな単位の依頼」で最も性能を発揮します。

- コンテキストの基本セット
  - 目的・受け入れ基準（例: 関数のI/O、計算量、境界条件）
  - Python/依存バージョン、禁止/許可ライブラリ（例: pandas使用可否）
  - ディレクトリ構成と対象モジュールの関係
  - スタイル/型/テスト基準（PEP8/ruff、mypy strict、pytestカバレッジ）
  - 実行コマンド（例: `pytest -q`、`python -m pkgname.main`）

- 依頼の粒度
  - 1依頼=レビュー可能な小さな変更（15〜30分で検証できる大きさ）
  - 「まず設計→同意→実装→テスト→修正」の順で段階化
  - 大規模変更は必ず差分（patch/diff）で依頼

- スレッド設計
  - タスクごとにスレッドを分け、履歴と前提の衝突を防ぐ

## 出力品質を上げるガードレール
次の「固定テンプレート」を最初に貼ると出力が安定します。

品質テンプレート（依頼の先頭に常に付ける）
```
前提:
- Python: 3.11
- スタイル: PEP8, black(line-length=100), ruff
- 型: mypy(strict=True), 可能な限り精密な型ヒント
- テスト: pytest + pytest-cov、既存テストは壊さない、境界条件のテストを含める
- ドキュメント: Googleスタイルのdocstring
- 依存: 標準ライブラリ優先。必要なら理由と併せて提案
```

実務ポイント
- PEP8/ruff: 自動整形と静的検査を前提に生成してもらう
- 型ヒント: mypyが通るまでLLMにフォローアップさせる
- Docstring: 使い方と例を生成させ、READMEに転記
- テスト: 正常系/異常系/境界を明示して要求

## すぐ使えるプロンプト集（実装）
1) 関数実装＋docstring＋型ヒント
```
あなたはPython開発の相棒です。次を満たす関数を src/pkgname/io.py に追加してください。
目的: ローカルCSVを読み込み、指定列でグループ化し合計を返す純粋関数
制約: pandasは使わずcsv/itertoolsで実装。大規模ファイルでもストリーム処理で動作
入出力:
- 入力: path:str, key:str, value:str
- 出力: dict[str,int]
品質: PEP8/black/ruff準拠、mypy(strict)を通す、Googleスタイルdocstring、例外はValueErrorで明示
出力: 完全な関数実装と使用例、必要なら小さなユーティリティも同ファイルに追記
```

2) CLI雛形（Typer）
```
目的: pkgname をCLIとして配布。`pkgname sum --file data.csv --key city --value amount` の形。
依存: typer[all] 使用可。loggingを実装、--verbose でDEBUG出力。
成果物: src/pkgname/cli.py と __main__.py、エントリポイント設定の追加方法（pyproject）も提案。
品質: 型ヒント/Docstring/簡単な例外処理/単体テスト雛形を併記。
```

3) FastAPI雛形（必要な人向け）
```
目的: /healthz と /sum エンドポイントを持つ最小FastAPI。
制約: uvicorn 実行例、Pydantic v2で入出力バリデーション、型厳格。
成果物: src/pkgname/api.py、tests/test_api.py（TestClientで疎通）。
```

## すぐ使えるプロンプト集（テスト/品質）
1) pytestテスト生成
```
対象: src/pkgname/io.py の group_sum 関数
要件: 正常系/空ファイル/キー欠損/負値/大きな入力のサブサンプリング
品質: AAAパターン、pytest.parametrize活用、ランダム性は固定シード
出力: tests/test_io.py の完全な内容
```

2) 失敗テストからの修正指示
```
次のpytest失敗ログから原因を仮説し、最小変更のpatch(diffs)を出し、影響範囲を説明してください。
--- ここに pytest のトレースバック全文 ---
制約: 既存の公開APIを壊さない。新規テストは最小限で追加。
出力: unified diff形式(---/+++と@@付き)で。
```

3) カバレッジ向上
```
現状: 行カバレッジ 78%、未達は src/pkgname/io.py:120-160 の枝分岐。
依頼: カバレッジ90%を目標に不足分だけ追加テストを提示。副作用やI/Oはモック化。
```

4) 型/静的解析の是正
```
mypy/ruff/blackの指摘一覧を貼るので、修正パッチと意図説明をください。
--- ここに mypy/ruff の出力 ---
```

## デバッグの実践：トレースバックの渡し方、最小再現、原因切り分け
- トレースバックは「実行コマンド・Python/OS・依存バージョン」とセットで渡す
- 最小再現コード（MRE）を一緒に貼るか、抽出を依頼する
- 原因仮説を複数提示してもらい、優先順位と検証手順を要求

依頼テンプレート
```
現象: 大きなCSVで KeyError が断続的に発生
環境: Python 3.11, macOS, pkgname 0.1.0, pandas 2.2.2
再現手順: `python -m pkgname.main --file big.csv`
ログ: --- ここにトレースバック ---
依頼: 1) 最小再現コードの抽出 2) 原因候補を3つ以内で提示 3) 最小変更の修正パッチ
```

## リファクタリングの進め方：差分依頼と後方互換チェック
大きな変更は「計画→部分差分→検証」の順で。

1) 計画提示を依頼
```
目的: io層とドメイン層の分離。公開APIは維持、内部だけ整理。
依頼: 影響範囲、マイグレーション手順、段階的コミット案（3段階）を提案。
```

2) 差分（patch/diff）で依頼
```
対象: src/pkgname/io.py, src/pkgname/domain.py
出力: unified diffで。関数移動はrename検出されるように説明をコメントで補足。
品質: 変更理由、後方互換性の確認観点、テスト更新も含める。
```

3) パッチの適用と検証
```bash
git checkout -b refactor/io-domain
# Claudeの提案を patch.diff に保存
git apply --check patch.diff   # 適用可能か事前確認
git apply patch.diff
pytest -q && mypy && ruff
```

後方互換の確認ポイント
- 公開関数/CLIの引数・戻り値が不変か
- 例外型・メッセージの互換
- 設定ファイル/環境変数/ファイルI/Oの仕様変更有無

## 日常ワークフロー例（設計→実装→テスト→レビュー）
1) 設計: 要件と受け入れ基準を箇条書きで提示→Claudeに設計案を出してもらい合意
2) 実装: 小さな関数単位で雛形生成→ローカルで整形/型/テスト
3) テスト: 正常/異常/境界を埋める→失敗時はログを貼り修正パッチを依頼
4) デバッグ: MRE化→原因仮説→最小修正の差分適用
5) リファクタ: 計画→差分→互換確認→段階適用
6) レビュー: 変更理由/影響範囲/テスト結果をClaudeに要約させ、PR説明文に流用

## 付録：最小のCI（GitHub Actions, Python）
```yaml
name: ci
on: [push, pull_request]
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with: { python-version: '3.11' }
      - run: python -m pip install --upgrade pip
      - run: pip install -e . pytest pytest-cov black ruff mypy
      - run: ruff check . && black --check . && mypy
      - run: pytest -q --cov=src --cov-report=xml
```

## 注意点（必ず目を通してください）
- 秘密情報: APIキーや個人情報は共有しない。ログはマスキング
- 依存のねじれ: Claudeの提案は環境とズレることがある。バージョンを明記
- ライセンス/セキュリティ: 外部コードや依存追加はライセンスと脆弱性を確認
- 過信しない: テストとレビューを通すまで本番適用しない

## まとめ
- 効率化の核心は「良いコンテキスト」「小さな依頼」「品質ガードレール」
- テンプレート化した前提（Python/スタイル/型/テスト）を毎回付けると安定
- 実装/テスト/デバッグ/リファクタは、差分駆動と最小再現で安全に前進
- 本記事のプロンプトをコピペして、まずは小タスクから「Claude Code Python 開発 効率化」を体感してください。
