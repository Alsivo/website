英日・日英の翻訳を業務へ入れるとき、最初に迷うのは「どれを何に使えば早いか」「用語統一やセキュリティは満たせるか」「コストは読めるか」。本稿は、この判断を短時間で終えるための“最短ルート”を先に示し、その後に根拠と運用の要点を整理します。

最終確認日：2026-08-15（日本時間）

## 先に結論：用途別“最短ルート”

### メール・チャット（文体調整・要約もしたい）

- **ChatGPT：** 丁寧/カジュアルなどのトーン指示や、要約・言い換えと合わせた下書き生成に向く。機密は投入しない運用を。

### 技術資料・仕様書（用語ブレを抑えたい／連携前提）

- **Google Cloud Translation：** 用語集、カスタム（AutoML/LLM枠）、ドキュメント翻訳などの機能をGCP内で一貫運用しやすい。
- **Microsoft Azure Translator：** カスタム翻訳（Custom Translator）とAPIを前提に設計しやすい。2026-06-06版APIで破壊的変更の告知あり、既存実装は影響評価を。

### 契約書・社外配布（取り扱い方針を明確にしたい）

- **DeepL（Pro/API Pro）：** 有料プランの入力は学習（モデル訓練）に使われない旨を公表。データ保持は必要最小限の一時的保存と案内。
- **みらい翻訳 FLaT：** 企業向けプラットフォーム。価格・条件は問い合わせベース（ID数・翻訳量に上限を設けないコンセプトを案内）。

### Web記事・社内ナレッジの一括変換（体裁も重視）

- **Google Cloud Translation：** ドキュメント翻訳や用語集を併用し、GCPワークフローで再現性を担保。

### 画像・PDF・Officeなどのファイル翻訳

- **DeepL（API含む）：** ドキュメント翻訳機能を提供。APIでワークフローに組み込みやすい。
- **Microsoft Azure Translator：** ドキュメント翻訳を提供（要件はドキュメント要確認）。

### 多言語展開・システム組み込み（英日以外も含む）

- **Google Cloud / Azure / Amazon Translate：** いずれも文字数ベース従量のAPI。カスタム用語やカスタマイズ機能で業務要件に合わせやすい。

### いくつかの注意

- 精度は言語対・分野・文体・用語管理の有無で変わるため「常に最も高精度」は断定しないでください。小規模PoCで実文書を比較しましょう。
- 評価用サービス（例：NICT TexTra）はデータ記録・出典表記義務があるため本番商用には不向きです。

## 失敗しない選び方：5つの基準

### 1) 精度と言語カバー（自社の実文書で検証）

まず、想定分野（技術・法務・カスタマーサポート等）の実文書で小規模PoCを。レビュー観点（用語固定、数値・単位、敬語、有責表現など）を事前に定義して差分を見ます。

### 2) ファイル（PDF/Office/画像）対応の有無と品質

- **DeepL** はドキュメント翻訳を提供し、APIで自動化しやすい。
- **Google Cloud Translation** はドキュメント翻訳の価格体系を公開。
- **Microsoft Azure Translator** もドキュメント翻訳を提供（利用要件はドキュメントで確認）。

### 3) 用語・スタイル制御

- **Google Cloud Translation：** 用語集（Glossary）やカスタム（AutoML/LLM枠）でドメイン適合を図れる。用語集の作成自体は課金対象外。
- **Amazon Translate：** カスタム用語（Custom Terminology）で訳語統一が可能（一致条件など仕様の把握が重要）。
- **Microsoft Azure Translator：** Custom Translatorでドメイン適合の学習が可能。

### 4) セキュリティ／データ取り扱い

- **DeepL（Pro/API Pro）：** 入力は学習に使われない、一時保存の扱いを公表。
- **Google Cloud Translation：** リージョン選択（例：EU内処理）など運用要件に合わせたエンドポイント設計を確認。
- **評価用サービス（TexTra）：** 入力データがサーバに記録、出典表記義務あり。商用本番は不適。
- ベンダーやプランで取り扱いが異なるため、運用前に必ず最新ドキュメントと自社規程の整合を確認しましょう（AzureやAWSの取り扱いも公式で要確認）。

### 5) コスト（見積りの勘所）

- 多くは「文字数」従量。**Google Cloud** のLLM翻訳は「入力と出力の双方」が課金対象。Basic/Advancedには月次クレジット（上限$10）が一括適用。
- **Amazon Translate** は文字数従量と無料利用枠の案内あり。
- **DeepL API Pro** は「月額基本料＋処理文字数の従量」課金を案内。
- **みらい翻訳 FLaT** は問い合わせベース（条件は公式で確認）、**みらい翻訳Plus** はFree/Starterなどプラン差を公開。

## 実務導入の“初期設定”チェックリスト

- **データ取り扱い・拠点の確認：**
 - DeepL（Pro/API）：学習不使用・一時保存の扱い。
 - Google Cloud：EU等の地域エンドポイント利用可否を確認。
 - Azure/AWS：料金・APIと合わせて取り扱い方針を最新ドキュメントで確認。
 - 評価用（TexTra）：本番用途に不向き（データ記録・出典表記義務）。
- **用語管理のセットアップ：**
 - Google Cloudの用語集（Glossary）を準備し、ドキュメント翻訳やバッチ処理と併用。
 - Amazon TranslateのCustom Terminologyで訳語統一。
- **ファイル翻訳の試行：** DeepL/Google/Azureでドキュメント翻訳の再現性・レイアウト保持を事前評価。
- **コスト試算の型を用意：** GoogleのLLM翻訳は入力＋出力でカウント。月次クレジットや無料枠の有無も踏まえて概算式を持つ。
- **PoCの設計：** 3〜5本の代表原文を「技術」「法務」「マーケ」などに分け、用語集有り/無しのABで差分を評価。

## 主要サービスの要点と使い分け

### DeepL（Pro/API Pro）

- **できることの例：** テキスト・ドキュメント翻訳、APIでの連携。
- **向いている人：** ファイル翻訳の再現性を重視し、ワークフローへAPI組み込みたい。
- **料金の考え方：** API Proは「月額基本料＋処理文字数の従量」課金。
- **注意点：** 有料プランの入力は学習不使用・一時保存の扱いを理解し、社内規程に合わせて運用設計。

### Google Cloud Translation（Basic/Advanced/LLM）

- **できることの例：** テキスト・ドキュメント翻訳、用語集、カスタム（AutoML/LLM枠）。
- **向いている人：** GCPでのシステム連携や地域エンドポイント等の要件と合わせて、一貫運用したい。
- **料金の考え方：** 文字数従量。LLM翻訳は入力＋出力の双方が課金対象、Basic/Advancedは月次クレジット適用。
- **注意点：** Glossary作成は課金対象外。EU等の処理ロケーションを要件に合わせて検討。

### Microsoft Azure Translator

- **できることの例：** テキスト・ドキュメント翻訳、Custom Translator。
- **向いている人：** 既存のAzure基盤でカスタム翻訳や運用統制を整えたい。
- **料金の考え方：** 文字数従量（料金は公式ページで見積）。
- **注意点：** 2026-06-06のAPIで破壊的変更の告知。既存実装は影響評価を。

### Amazon Translate

- **できることの例：** リアルタイム/バッチ翻訳、Custom Terminologyで訳語統一。
- **向いている人：** 既存のAWSワークフローへ統合し、運用の中で用語統制を効かせたい。
- **料金の考え方：** 文字数従量。無料利用枠の案内あり。
- **注意点：** Custom Terminologyの一致条件など仕様を事前に把握してPoCに反映。

### みらい翻訳（FLaT / Plus）

- **FLaT（企業向け）：** ID数・翻訳量に上限を設けないコンセプト。価格・条件は問い合わせベース。
- **Plus（個人〜小規模）：** Free/Starter等のプラン差を公表。販売チャネルにより提供条件が異なる場合あり。

### YarakuZen（日本発の翻訳支援SaaS）

- **特徴：** 複数翻訳エンジン（DeepL/Google/Microsoft等）対応、用語集・チーム共有・SSOやIP制限などの法人機能を公表。
- **使いどころ：** 「1つのUIで複数エンジンを比較・使い分けたい」チームに。各エンジン側の契約条件との整合を運用で担保。

### ChatGPTでの翻訳活用（補助的に）

- **使いどころ：** メールの丁寧表現、要約、言い換え、見出し生成と翻訳を一度に試す。
- **運用上の注意：** 機密は投入しない。最終稿は人がレビュー。

### 評価用サービス：NICT「みんなの自動翻訳＠TexTra」

- **前提：** 評価・試験利用が目的。入力データのサーバ記録、出典表記義務あり。本番用途は不適。

## 品質を一段上げるコツ（短時間で効く）

- **用語集を先に作る：** GoogleのGlossary、AWSのCustom Terminologyを用意してから比較すると効果が見えやすい。
- **文を短く：** 1文1メッセージで係り受け崩れを防ぐ。
- **指示は具体的に：** 読者層（経営層/一般ユーザー）、トーン（丁寧/カジュアル）、意訳の可否などを明示。
- **ABテスト：** 用語集あり/なし・モデル（Basic/Advanced/LLM等）で結果差を可視化。

## よくある質問

### まずどれを試せばよいですか？

メールなどの下書き・文体調整はChatGPT、ファイル翻訳や自動化はDeepLやAzure、GCP/AWSと既存システム連携はGoogle Cloud/Azure/Amazon Translateから始めると全体像を掴みやすいです。Googleは用語集やドキュメント翻訳、LLM翻訳の料金枠を公式で公開しています。

### 無料やクレジットはありますか？

Google Cloud TranslationはBasic/Advancedに月次クレジット（上限$10）を案内しています。Amazon Translateは無料利用枠の案内があります。みらい翻訳PlusにはFree/Starterなどのプラン差が公表されています。条件は必ず公式の最新情報で確認してください。

### 機密性の高い文書は安全に扱えますか？

DeepLの有料プラン（Pro/API Pro）では、入力は学習（モデル訓練）に使われない旨が公表されています。ほかのサービスも取り扱いはプランや機能で異なるため、料金・ドキュメント・規約を併せて公式で最新確認してください。

### PDFやPowerPointなどのファイルは翻訳できますか？

DeepLはドキュメント翻訳とAPIを提供しています。Google Cloud Translationはドキュメント翻訳の価格体系を公開しています。Microsoft Azure Translatorもドキュメント翻訳を提供しています（要件はドキュメントで確認）。

### 用語を固定（社名・製品名など）できますか？

Google Cloudは用語集（Glossary）を提供し、作成自体は課金対象外です。Amazon TranslateはCustom Terminologyで訳語統一が可能です。いずれもPoCで仕様を確認してから運用に組み込んでください。
